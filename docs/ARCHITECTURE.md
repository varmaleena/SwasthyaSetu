# Trust boundaries and implementation choices

React/TypeScript PWA → FastAPI → one database per fictional state. Production mode refuses SQLite and identical database URLs. The shipped SQLite mode is only a local convenience; portable PostgreSQL and Docker Compose are also available.

State-scoped signed tokens authorize 24-hour synthetic judge sandboxes. Each database row has compound state/session identity. Guest-selected roles simulate officers inside that sandbox; they are not independently authenticated officials. Every mutation holds the session row lock, checks versions, stores an idempotent response and writes an audit record in the same transaction. Balance constraints protect reservations and quarantine. Receipts use distinct destination lot rows and preserve transit quantities. No cross-state shipment route exists.

The stock ledger is normalized. Small ancillary entities (capacity, forecasts, plans, evidence metadata, drafts, audits and jobs) use typed API contracts plus a scoped versioned JSON records table. This intentionally differs from one table per ancillary entity in the blueprint. Database columns enforce hard stock/shipment invariants; API models enforce capacity invariants.

Gemini returns extraction drafts only. The adapter uses actual Google GenAI calls and records model/usage/latency. No fake provider implementation is available in the app. Private Supabase evidence is served through ownership checks. Local evidence is stored in the development database, explicitly labelled. WAV duration is checked from its PCM header, not client-supplied duration. Provider attempts are bounded and failures consume application quota. Provider calls are not exactly-once across process failure; no automatic retry is enabled.

Forecasts load trusted JSON coefficients; never pickle. Training uses only the first 120 days, moment calibration uses days 120–149, selection uses days 150–179. Final evaluation generates independent synthetic histories and compares the final 28 days. Evaluator-only latent demand never enters serving databases. Shared coefficients cover intercept, weekend and log footfall; shrunken facility/product intercepts remain local during federation. 100 seeded paths include shared shocks. Baseline is retained and selected automatically if validation is better.

Allocation uses OR-Tools CP-SAT with integer packs, bounded runtime, hard batch exclusions, donor protection, route authorization and arrival-before-depletion checks. Independent verifiers recompute quantity, product, freshness and donor protection constraints. The guided graph supports B/C → A; the network graph supports all eight fictional facilities across districts. Its three bounded stages minimize unmet units, then maximum relative shortage, then transport/expiry cost. A non-optimal stage is labelled feasible, never globally optimal. Entire plans reserve atomically. No live traffic or geocoding service is used.

Hosted federation uses separate database adapters in a shared process. The coordinator accepts only a strict parameter/aggregate contract; raw rows are rejected. `scripts.federation_check` launches two actual local processes, each with only its own database connection environment. The shared OS/filesystem is not a security boundary. Three persisted job steps perform two local updates and candidate validation. Session locking serializes competing advances; transaction rollback makes an interrupted step resumable. Candidate acceptance stays in the sandbox; global model publication is unavailable to guests.

Free-tier safeguards: no cloud creation scripts, no automatic upgrades, no always-on worker, no scheduler, no artificial keepalive. Database-backed request limits; bounded media and responses; state evidence budget 45 MiB. Evidence budget is conservative and does not automatically reclaim space when session metadata expires. Owner must remove expired objects and reconcile the counter before it is reused. This is a deployment-maintenance limitation, not silent unbounded storage.
